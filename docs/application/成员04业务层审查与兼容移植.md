# 4号同学Application层审查与兼容移植记录

## 输入
- `4.zip`：42个文件，包含另一套领域模型（Models）、8个仓储抽象与IUnitOfWork、查询用例、CourseCommand、字段校验和交接说明。
- 现行 `main`：`ICampusService/ICampusRepository` 单服务契约，已集成3号API、5号数据库及真实Windows CI烟测。

## 值得保留并验证的业务规则
1. 当前学生由`active_demo_student_id`决定，不接受前端指定任意`studentId`。
2. 未公布成绩`score=null`、`gradePoint=null`保持原样，禁止推算虚构GPA。
3. 考试按日期顺序展示，未公布日期的安排置于末尾。
4. 同周同节的课程发生冲突；不同周（单双周）可错开。
5. 字段校验要返回可以定位字段的错误；课程新增与修改使用相同规则。
6. 存储的学期日期和考试时间属于可信边界，异常值应映射到统一的数据库不可用响应。
7. 成绩或考试存在时禁止删除课程，避免级联删除信息。

## 本次实施

- 修复Infrastructure持久化日期、考试时间无效时可能返回HTTP 500的错误分类，改为`503 db_unavailable`。
- 增加真正HTTP回归测试：未公布分数/绩点仍为null、未排期考试在末尾、共享种子课程本地写入口拒绝编辑与删除、坏日期和坏考试时间返回503。
- 继续保留原有11条路由、公共DTO与数据库迁移历史；无官方智慧安大账号和数据访问。

## 4号源包存在的集成问题（因此没有整包覆盖）
- 该包的Application接口和领域模型与现行ICampusRepository/ICampusService不兼容，直接替换将要求3、5号重新实现多处映射与Repository。
- `CourseCommand.UpdateAsync/DeleteAsync`通过`FindAsync(courseId)`操作课程，没有先验证活动学生是否拥有该课程；存在越权修改或删除的风险。
- 4号方案允许直接编辑共享课程并通知其他选修者；现行系统采用更严格的策略：只能改本人新建的`local-*`课程，不允许更改共享种子行。
- 4号方案中校验的课程名称、教师与地点长度上限是60/40/60；当前已冻结契约是120/100/150，不能悄悄收紧输入范围。
- 4号源代码没有一套可直接在当前GitHub方案运行的完整自动化集成测试；其交接文档明确表述提交时尚未本机编译。
