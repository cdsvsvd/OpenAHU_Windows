## 审查发现

1. **不能直接整体覆盖**：成员05的仓储实现引用`OpenAHU.Application.Abstractions`等8个不同接口；目前主分支使用`ICampusRepository`和`ICampusService`，硬复制将发生类型、构造与DI冲突。
2. **不能混用首次迁移**：成员05的`20261105071817_InitialCampusSchema`和主分支的`202611050001_InitialLocalDatabase`迁移历史不同。不能删除已有迁移来让已创建的本地数据库重新建表。
3. **个人写权限需要再审查**：成员05报告指出4号部分写操作按全局课程ID处理。未来多学生实际场景需要明确所有权/选课关系，当前本机单一演示学生模型不能直接视作多账户安全设计。
4. **SQLite约束改进需要向前迁移**：单一当前学期索引、不同UTC偏移下考试时间排序、decimal映射等都值得采用，但必须在当前迁移基础上新增版本并验证已有数据可保留，不能无计划直接切换实体与数据库结构。
5. **最早的手写迁移快照未规范化**：当前主分支针对EF模型不一致暂时忽略PendingModelChangesWarning。正式发布前需生成并评审正确快照，再取消该抑制并增加漂移测试。微软不推荐长期忽略该警告。

## 已兼容移植到现行基线

- 检查现有SQLite文件是否具有本程序认可的迁移历史，在执行`MigrateAsync`前使用只读连接拒绝未知、更新或不完整的数据库，避免覆盖用户资料。
- 仅在业务表完全为空时首次写入虚构演示数据，并用`demo_seed_version=v1`标志防止异常重复灌入；已有数据不清空或补齐。
- 数据库迁移失败时由启动状态门禁令`/health`报告`databaseReady=false`；不能仅凭残留学生记录报告就绪。
- EF Core/SQLite统一升级到10.0.14，补充Windows CI的现有/未管理库保护验证。
- 保留目前已经通过的API、DTO、JSON与11条路由，不导入另一套重复实现。
