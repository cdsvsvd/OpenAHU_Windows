# 数据库初始化、迁移、备份和升级

适用：成员05数据库基础及仓储实现。基线为 main `8dd479eb63704b0bfb37d591bda30b3c535ac75f`；最新读写接入说明见05号文档。

## 1. 工程和工具

- .NET 10；EF Core Sqlite / Design / dotnet-ef 固定为 10.0.11。
- `src/OpenAHU.Infrastructure` 是类库，引用 Application 以实现其仓储接口；不引用 Contracts、WPF 或 ASP.NET Core。
- 数据库正式结构以 `Migrations/` 为准；禁止同时对运行库执行任务包建表 SQL 和首次迁移。
- 迁移文件、实体和代码入库；运行中的 `.db`、日志侧文件和工具二进制不入库。

## 2. 首次初始化

API 接入前，可以从仓库根目录使用独立核验工具：

```powershell
$taskDatabase = Join-Path ([IO.Path]::GetTempPath()) 'OpenAHU-member05-demo/campus.db'
dotnet run --project src/OpenAHU.Infrastructure/Tools/OpenAHU.DatabaseTool.csproj -c Release -- --database-path $taskDatabase
```

初始化步骤：创建专用目录 → 检查已有结构/迁移版本 → 应用待执行迁移 → 对完全空的业务库插入固定演示数据 → 检查表、外键和当前演示资料。

Windows 下新建的数据库目录会关闭权限继承，只授予当前用户完全控制。默认的 OpenAHU 运行目录即使已存在也会收紧权限；调用方指定的既有目录不会被改权限，因此测试、部署时应使用当前用户拥有的专用目录，不传入共享目录。

Seed 同步和异步入口都已实现，使用 EF 的迁移锁保护。数据一次 SaveChanges 提交，避免半套演示数据。已有任何业务记录或设置时不填充、不合并、不覆盖。即使用户删除了全部课程，seed 标记也会保留，不会在下次启动恢复课程。[EF Core 初始化数据说明](https://learn.microsoft.com/en-us/ef/core/modeling/data-seeding)

## 3. 只读就绪检查

```powershell
dotnet run --project src/OpenAHU.Infrastructure/Tools/OpenAHU.DatabaseTool.csproj -c Release -- --database-path $taskDatabase --check-only
```

探针使用只读连接，不建库、不迁移、不写 seed。检查：迁移版本完整且匹配、九张业务表存在、SQLite quick_check、外键检查，以及 active_demo_student_id 对应学生确实存在。

结果只包含就绪状态、基础设施状态分类和通用提示，不含路径、SQL 或连接串。它不是 HealthDto；3号负责转换为 HTTP 响应，不能将 DbContext 或实体交给前端。

## 4. 生成后续迁移

先与4号/3号确认字段及契约影响，修改实体/映射，再在 Infrastructure 项目目录执行：

```powershell
dotnet tool restore
dotnet ef migrations add <英文迁移名称> --output-dir Migrations
dotnet ef migrations has-pending-model-changes
dotnet ef migrations script --output <仓库外的审查文件.sql>
```

必须审查 Up/Down 和生成 SQL。正式启动调用 CampusDatabase.InitializeAsync，不调用 EnsureCreated。EF CLI 直接更新不会执行本项目的全部初始化前置检查，建议只对全新临时库或已核验并备份的开发库使用。

```powershell
# 必须先创建一个专用临时目录；路径仅为示例，不要替换成未知来源的既有库。
dotnet ef database update -- --database-path <临时目录内的绝对数据库路径>
```

SQLite 的部分结构变更需要重建表，不支持通用幂等迁移脚本。当前没有旧版正式数据库可供升级，本次验证了首次迁移、重复初始化、临时库回退到0再重建；未来真实版本升级仍需单独验证保留数据。[SQLite 提供程序限制](https://learn.microsoft.com/en-us/ef/core/providers/sqlite/limitations) · [迁移部署说明](https://learn.microsoft.com/en-us/ef/core/managing-schemas/migrations/applying)

## 5. 备份和恢复

1. 关闭桌面端及所有后端/数据库工具，确认没有进程继续写库。程序内备份应先释放 DbContext/连接并清理对应连接池。
2. 为迁移前版本保存独立备份，记录应用版本、迁移列表、备份时间。未完成 checkpoint 的 WAL 数据不能遗漏：离线时保留数据库及仍存在的对应侧文件；在线备份应通过 SQLite 备份 API，不能只复制正在写入的主文件。
3. 先在备份副本上验证 quick_check、foreign_key_check 和课程数量，再尝试升级。
4. 恢复时保持应用关闭，保留失败现场，恢复一套一致的备份并使用兼容的应用版本；不要把来自不同时间点的主文件和 WAL 混在一起。
5. 不对用户库执行 `database update 0` 或删除重建来“修复”。首次迁移的 Down 会删除所有业务表，只用于可丢弃的测试库。

当前提供备份操作说明，尚未实现用户界面的备份/恢复按钮，也没有执行用户正式库的备份或升级。

## 6. 失败处理

| 情况 | 当前处理 |
| --- | --- |
| 非 EF 管理的已有表/样例 SQLite | 返回 IncompatibleSchema，不给它伪造迁移历史、不覆盖 |
| 高于或偏离本程序的迁移历史 | 返回 IncompatibleSchema，不自动降级 |
| 损坏、只读、文件被占用、目录不可写 | 返回 Unavailable，保留原文件 |
| 迁移缺失、业务表缺失 | 探针不就绪，不自动修复 |
| 当前演示资料无效、外键异常 | 返回 InvalidData，不用 seed 覆盖修复 |
| 调用方主动取消 | 保留取消语义，抛出取消异常 |
| 迁移锁等待超时 | 返回 Unavailable，不自动删除锁 |

默认 SQLite busy timeout 为5秒、初始化取消期限30秒。SQLite 部分调用同步等待，取消不保证精确到毫秒。若进程在迁移中崩溃，EF 的迁移锁可能残留；必须先确认没有迁移进程并备份，再由开发者根据官方说明处理，不能启动时无条件清除锁。

## 7. 与参考结构的差异和待定业务规则

- 增加“最多一个当前学期”的过滤唯一索引，与现有 TermDto 说明一致。
- 考试开始/结束使用带偏移的 ISO 文本；约束用 julianday 比较实际时间，避免不同偏移的文本排序错误。
- C# 学分、分数、绩点使用 decimal；SQLite 保留参考结构的 REAL 亲和性，不宣称任意精度的小数存储。
- 数据库存储星期1..7，周日7；未来适配4号模型时只转换一次。
- 周次1..30是数据库底线；4号业务层已校验不超过学期week_count、写入至少一个周次和排课时间冲突，仓储不重复实施表单规则。
- 外键动作沿用参考SQL；4号明确有成绩或考试时拒绝删除，无关联时可以删除共享课程并返回影响人数。数据库删除另用原子条件保护检查后新增的关联记录；此类并发变化暂返回受控不可用，后续由4号完善409分类。
- UpdatedAt 已由4号固定首版为null，不使用数据库文件时间伪装业务更新时间。
